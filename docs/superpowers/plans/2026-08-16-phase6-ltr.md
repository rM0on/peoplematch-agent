# Phase 6 Learning-to-Rank Implementation Plan

> **For agentic workers:** Execute this plan task-by-task with a red-green test cycle for each contract.

**Goal:** Add one deterministic LightGBM LambdaMART ranker over frozen Phase 5 features, trained and evaluated only on explicit Train/Dev judgments.

**Architecture:** Offline dataset/training/metrics modules will read frozen labels and split metadata, while runtime ranking will depend only on retrieval, the frozen FeatureVector contract, and a validated native model artifact. A Job→Candidates API will retrieve one Hybrid pool, reuse Phase 5 extraction, score the ordered ten-feature matrix, and rerank within that pool with deterministic ties.

**Tech Stack:** Python 3.9.13, Pydantic v2, FastAPI, existing Phase 4/5 services, LightGBM 4.6.0 native Booster text format, pytest.

## Global Constraints

- Preserve the Phase 5 feature fingerprint `dc85c7237c6c67785199d221c919ae48c31c9a6323857070e6399d3eae365e42` and exact `MODEL_FEATURE_ORDER`.
- Use only explicit Train/Dev relevance labels; unjudged pairs are excluded, never grade 0.
- Never read or evaluate frozen Test Jobs; never modify Phase 4, Phase 5, dataset, labels, or splits.
- Canonical objective is `lambdarank` with label gain `[0, 1, 3, 7]`; do not implement `rank_xendcg`.
- Convert nullable feature values to NaN and rely on LightGBM native missing handling.
- Keep runtime imports free of labels, splits, pairwise, hard-negative, and evaluation modules.
- Do not commit, push, or start Phase 7 in this task.
- LightGBM 4.6.0 is the latest compatible pinned release for the current Python 3.9.13 runtime; LightGBM 4.7.0 requires Python 3.10 or newer. This is a runtime compatibility constraint, not model tuning.

### Task 1: Dependency and contracts

Add and install `lightgbm==4.6.0`. Add ranking schemas/contracts and typed ranking errors. Tests pin the feature order, fingerprint, LightGBM version, objective, label gain, request bounds, and runtime/offline dependency boundary.

### Task 2: Derived Train/Dev dataset

Add an offline builder that calls the existing Hybrid retrieval and Phase 5 feature service with `top_k=48`, joins only explicit Train/Dev labels, asserts 168/60 rows and 14/5 groups, serializes a canonical artifact, and computes a stable artifact fingerprint. Add tests for no Test/unjudged rows, no ID leakage into X, joins, source hashes, and deterministic fingerprints.

### Task 3: Metrics and deterministic trainer

Add judged-set NDCG@5/NDCG@10, MRR at relevance ≥2, and pairwise accuracy with 0.5 ties. Train one deterministic LambdaMART Booster with the frozen baseline parameters, validate finite/nonconstant predictions, repeat-training determinism, and serialize a native text model plus provenance metadata.

### Task 4: Model loader and runtime service/API

Validate model existence, SHA-256, ranker version, feature version/fingerprint, and feature order before prediction. Add Job→Candidates-only ranking with `candidate_pool_k` and `top_k`, one Hybrid retrieval call, Phase 5 reuse, raw score output, and deterministic score/rank/entity tie-breaking. Add service/API and leakage tests.

### Task 5: Artifacts, documentation, and verification

Generate the tracked Train/Dev dataset, metadata, and judged-set Dev report; keep the native model under ignored `artifacts/phase6`. Update README, architecture, API design, roadmap, and `docs/ltr-ranking.md` without Test metrics or production claims. Run focused tests, backend/integration/frontend gates where available, artifact/freeze checks, and review the final diff. Do not commit.
